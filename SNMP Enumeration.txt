SNMP Enumeration

## What is SNMP?

**SNMP (Simple Network Management Protocol)** is used to monitor and manage network devices and systems.

It can expose information such as:

- Hostname
- Operating system
- System description
- Administrator/contact information
- Network interfaces
- Running processes
- Installed software
- Storage information
- Custom scripts and their output
- Device location
- System uptime

> ⚠️ SNMP can expose sensitive information when poorly configured.

---

# SNMP Versions

| Version | Security |
|---|---|
| SNMPv1 | No authentication/encryption |
| SNMPv2c | Community string, sent in plaintext |
| SNMPv3 | Authentication + encryption support |

### Community String

A community string acts similar to a password for SNMPv1/v2c.

Common default:

```text
public

Another commonly encountered string:

private
Important SNMP Ports
Port	Protocol	Purpose
161/UDP	SNMP	Queries/commands
162/UDP	SNMP Trap	Trap notifications
MIB and OID
MIB

MIB (Management Information Base) is a hierarchical collection of objects that can be queried through SNMP.

OID

OID (Object Identifier) identifies a specific SNMP object.

Example:

.1.3.6.1.2.1.1.1.0

This corresponds to the system description (sysDescr).

SNMP Enumeration Methodology
1. Discover UDP/161
        ↓
2. Identify SNMP
        ↓
3. Find/validate community string
        ↓
4. Run snmpwalk
        ↓

        ↓

        ↓

1. Discover SNMP

Scan UDP port 161:

sudo nmap -sU -p161 <TARGET>

Service/version detection:

sudo nmap -sU -p161 -sV <TARGET>

SNMP information using NSE:

sudo nmap -sU -p161 --script=snmp-info <TARGET>

Example:

161/udp open snmp
2. Enumerate Community Strings

onesixtyone can be used to test a list of community strings.

onesixtyone -c /path/to/snmp_communities.txt <TARGET>

Example:

public

If public works, SNMPv2c enumeration can be performed using:

snmpwalk -v2c -c public <TARGET>

Query Specific OIDs

Instead of walking everything, query a specific OID:

snmpwalk -v2c -c public <TARGET> <OID>

Example:

snmpwalk -v2c -c public <TARGET> .1.3.6.1.2.1.1

This queries the SNMP system information tree.

Custom SNMP Scripts

During enumeration, don't only look at standard system information.

SNMP can expose custom extensions/scripts.

In the HTB lab, the HOST-RESOURCES-MIB revealed:

/usr/share/flag.sh

The custom extension was indexed using the name:

FLAG

The output was exposed through SNMP:

HTB{5nMp_fl4g_uidhfljnsldiuhbfsdij44738b2u763g}
Key Lesson

If SNMP exposes custom script/extension information:

Custom script
      ↓
SNMP MIB entry
      ↓
Script output
      ↓
Potentially sensitive information
NET-SNMP Extension Enumeration

Net-SNMP can expose extension-related objects.

Useful branch:

.1.3.6.1.4.1.8072

You may encounter references to:

nsExtendConfigTable
nsExtendOut1Table
nsExtendOut2Table

If available, enumerate the relevant Net-SNMP extension tree.

BRAA

braa can query individual SNMP OIDs.

Example:

braa public@<TARGET>:.1.3.6.1.2.1.*

More focused queries can be used when a specific MIB branch is known.

What to Look For

When you obtain a valid community string, prioritize:

✓ sysDescr
✓ sysContact
✓ sysName
✓ sysLocation
✓ Network interfaces
✓ Running processes
✓ Process parameters
✓ Installed software
✓ Storage
✓ Custom MIBs
✓ SNMP extensions
✓ Custom scripts
✓ Script output
